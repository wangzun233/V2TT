# 客户端更新提醒

从 Windows 0.2.3、Android 0.1.2 开始支持。更早版本没有此功能，必须先手动覆盖安装一次。

## 用户操作

- Windows：安装版启动后检查一次，运行期间每 6 小时检查；同一新版每次运行只自动提示一次。托盘图标右键 → 检查更新，可随时重试。
- Android：启动时检查，设置 → 应用设置中可开关自动检查，并使用检查更新入口。已有用户手动关闭的开关不会被强行打开。
- 发现新版弹窗后，确认可打开 V2TT 官方 GitHub 发布页，查看说明并选择对应系统安装包。
- 不会自动下载、静默安装或远程执行命令。检查和打开发布页不会主动断开代理；真正覆盖安装前应退出客户端，不要清除个人数据。
- 更新检查失败与“没有新版本”分别处理。不上传订阅、账号、服务器配置或设备标识；只向 GitHub 请求公开更新索引。

这不是应用关闭后的系统推送，也不是一键后台替换程序。Android 的安装包由系统验证签名，Windows 仍需用户确认安装；当前 Windows 包尚无正式代码签名。

## 发布步骤

更新源固定为 `https://raw.githubusercontent.com/wangzun233/V2TT/main/updates/stable.json`，不允许由订阅更改。

1. 分别递增 `windows/package.json` / 锁文件的版本、`android/version.properties` 的版本和 versionCode。
2. 构建并验证两端安装包，生成 SHA256，完成脱敏检查。
3. 在本仓库发布对应 Release，上传 Windows EXE、ARM64 APK、源码和校验值；确认附件可下载。
4. 最后更新 `updates/stable.json` 并推送 main。索引中的两个 releaseUrl 必须是已经存在的本仓库 Release 页面，不能写其他网站或安装器路径。
5. 使用旧版支持更新的客户端检查，确认新版本弹窗；再检查最新版不会重复报新版本。

本轮发布标签为 `v2026.09.11-update-preview`，用户已于 2026-09-12 授权发布。没有完成第 3、4 步，线上提醒不会生效。不要先发布索引再上传包。

版本按三段数字比较，拒绝格式错误、跨仓库地址和降级；Android 同时要求 versionCode 增加。请求有超时、16 KiB 内容上限和 HTTPS 校验，不携带 GitHub 凭据。GitHub 暂时无法访问时可稍后手动重试，不会切换代理规则。

发布配置中的 stable 指默认推荐通道，不等同于产品已经脱离预览阶段。要撤回尚未推广的版本，可把索引恢复到之前版本；已安装的新版不会自动降级。
